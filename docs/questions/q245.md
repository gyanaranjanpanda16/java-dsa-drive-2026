# Q245 — Sort by repeatedly selecting the smallest remaining value

**Topic:** Elementary sorting · **Level:** Easy

## Problem and accepted inputs

Return a sorted copy using selection sort.

## Example

```java
solve(new int[]{3,1,2})
```

Expected Java value: `new int[]{1,2,3}`.

Expected printed output (verified):

```text
[1, 2, 3]
```

## How, why, and where to use it

At step i, choose the minimum of the unresolved suffix and place it at i. The fixed prefix then contains exactly the i+1 smallest values in order. This teaches selection and minimizes swaps, but the standard swap version is not stable.

## Worked trace

[3,1,2] selects1 into index0, then2 into index1.

## Line-by-line reasoning

- `public static int[] solve(int[] input) {` — Make mutations local to the returned copy.
- `int[] a=input.clone();` — Every later swap preserves the original multiset of values.
- `for(int i=0;i<a.length;i++) {` — Grow the finalized sorted prefix one element at a time.
- `int smallest=i;` — Initially consider the first unresolved value the minimum.
- `for(int j=i+1;j<a.length;j++) if(a[j]<a[smallest]) smallest=j;` — Search the complete unresolved suffix.
- `int saved=a[i]; a[i]=a[smallest]; a[smallest]=saved;` — Place its minimum at the next final position.
- `return a;` — The finalized prefix eventually spans the entire array.

## Complexity and tradeoffs

O(n²) comparisons in all cases, at most O(n) swaps; O(n) output copy.

## Cases to practise

- `solve(new int[]{3,1,2})` → `new int[]{1,2,3}`: The minimum moves into each prefix slot.
- `solve(new int[]{})` → `new int[]{}`: No selection needed.
- `solve(new int[]{4,4,1})` → `new int[]{1,4,4}`: Equal values remain present.
