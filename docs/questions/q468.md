# Q468 — Reach the furthest building with bricks and ladders

**Topic:** Greedy resource allocation · **Level:** Medium

## Problem and accepted inputs

Given int building heights, nonnegative long bricks, and a nonnegative number of ladders, start at index0. A positive climb costs that many bricks or one ladder; flat or downward moves are free. Return the furthest reachable index, or -1 for no buildings. Heights may span the int domain.

## Example

```java
solve(new int[]{4,2,7,6,9,14,12},5,1)
```

Expected Java value: `4`.

Expected printed output (verified):

```text
4
```

## How, why, and where to use it

Using ladders on the first climbs can waste them on small gaps. Keep positive climbs in a min heap as tentative ladder uses. Whenever there are more climbs than ladders, pay bricks for the smallest climb. This reserves ladders for the largest climbs seen so far. Swapping a ladder from a smaller to a larger climb cannot increase brick use, which proves the greedy assignment is optimal for each prefix. This models allocating a limited number of fixed-cost exemptions to the most expensive transitions.

## Worked trace

For heights [4,2,7,6,9,14,12], bricks5,ladders1: descent4→2 is free. Reserve the ladder for climb5 to7. Climb3 to9 makes two candidates, so pay3 bricks and keep the ladder on5. The next climb5 forces another5-brick payment, but only2 remain; return index4, height9.

## Line-by-line reasoning

- `public static int solve(int[] heights,long bricks,int ladders) {` — Evaluate each reachable prefix with its cheapest brick allocation.
- `if(bricks<0||ladders<0) throw new IllegalArgumentException("nonnegative resources required");` — Resource budgets cannot be negative.
- `PriorityQueue<Long> climbs=new PriorityQueue<>();` — Keep tentative ladder climbs ordered from smallest to largest.
- `for(int i=0;i+1<heights.length;i++) {` — Try the next building in the fixed sequence.
- `long climb=(long)heights[i+1]-heights[i]; if(climb<=0) continue;` — Flat and downward transitions consume no resources.
- `climbs.add(climb);` — Tentatively reserve a ladder for this positive gap.
- `if(climbs.size()>ladders) {` — Too many reservations require paying for the cheapest one.
- `long cost=climbs.remove();` — All remaining heap entries are at least this large.
- `if(cost>bricks) return i;` — Even the cheapest assignment cannot cross to i+1.
- `bricks-=cost;` — Pay once and retain ladders for the larger climbs.
- `return heights.length-1;` — This is also -1 when the input is empty.

## Complexity and tradeoffs

O(n log(min(n,ladders+1)+1)) time and O(min(n,ladders+1)) heap space. Long differences prevent overflow when heights cross the signed int extremes.
