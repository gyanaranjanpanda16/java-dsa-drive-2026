# Q293 — Select the k most frequent integers

**Topic:** Hashing and heaps · **Level:** Medium

## Question and contract

Select the k most frequent integers. Implement the operation exposed by `String solve(int[] a,int k)`. k>=0; returns at most k distinct values; input remains unchanged.

## Runnable example

```java
solve(new int[]{3,3,1,1,2},2)
```

Expected output:

```text
[1, 3]
```

## How and why the answer works

Counting converts repeated input into distinct candidates with priorities. A priority queue orders frequency descending and value ascending, so each poll is the best remaining candidate.

## Walkthrough

For [3,3,1,1,2], the frequencies are 1→2,2→1,3→2. Requesting two frequent values selects 1 and 3. Their counts tie, so the defined ascending-value tie-break prints [1,3]. Frequency order and numeric order are separate decisions; a HashMap's traversal order must not decide the result.

## Complexity and tradeoffs

O(n+u log(u+1)) time and O(u) storage for u distinct values. This cost describes the supplied representation and stated input contract. A more general version may need extra validation or a different representation; do not silently extend the assumptions.

## Read the important code decisions

These statements connect the algorithm to Java. Follow how each one changes the state used by the next statement; the linked answer contains the complete method.

- `Map<Integer,Integer> counts=new HashMap<>();` — Frequency is separate from the numeric value itself.
- `PriorityQueue<Integer> heap=new PriorityQueue<>((x,y)->counts.get(x).equals(counts.get(y))?Integer.compare(x,y):Integer.compare(counts.get(y),counts.get(x)));` — Higher frequency wins; smaller value breaks ties.
- `heap.addAll(counts.keySet());` — Store each distinct candidate only once.
- `while(result.size()<k&&!heap.isEmpty()) result.add(heap.poll());` — Stop if fewer than k distinct values exist.
- `return result.toString();` — Output is ranked by the documented priority.
