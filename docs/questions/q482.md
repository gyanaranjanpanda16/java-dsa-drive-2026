# Q482 — Reverse all32 bits and return their unsigned value

**Topic:** Bit manipulation · **Level:** Easy

## Problem and accepted inputs

Reverse the32-bit pattern of any int and return its unsigned numeric value as a long.

## Example

```java
solve(1)
```

Expected Java value: `2147483648L`.

Expected printed output (verified):

```text
2147483648
```

## How, why, and where to use it

Read the low bit of the input and append it to the growing result, then shift the input logically. Exactly32 iterations preserve leading and trailing zeros, unlike decimal digit reversal. Useful for bit-oriented encodings and permutation exercises.

## Worked trace

Input1 has only its lowest bit set; reversal places it at bit31, producing unsigned2147483648.

## Line-by-line reasoning

- `public static long solve(int value) {` — Use long so a reversed sign bit is displayed as a nonnegative unsigned value.
- `long reversed=0;` — The result initially contains no processed bits.
- `for(int i=0;i<32;i++) { reversed=(reversed<<1)|(value&1); value>>>=1; }` — Append one original low bit and discard it using zero-fill shift.
- `return reversed;` — Exactly32 appends keep the result within the unsigned32-bit range.

## Complexity and tradeoffs

O(32) time and O(1) space.

## Cases to practise

- `solve(1)` → `2147483648L`: The lowest bit becomes the highest.
- `solve(-1)` → `4294967295L`: All bits stay set.
- `solve(0)` → `0L`: All bits stay clear.
