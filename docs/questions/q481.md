# Q481 — Compute the bitwise AND of an inclusive integer range

**Topic:** Common binary prefixes · **Level:** Medium

## Problem and accepted inputs

For0<=left<=right<=Integer.MAX_VALUE, return the AND of every integer in[left,right].

## Example

```java
solve(5,7)
```

Expected Java value: `4`.

Expected printed output (verified):

```text
4
```

## How, why, and where to use it

Every changing low bit becomes zero somewhere across the interval. Only the common high-bit prefix survives, so shift both endpoints until equal and restore their shared prefix. Useful for reasoning about bitmask ranges without iterating over their numeric span.

## Worked trace

5,6,7 are101,110,111; their shared prefix is1 at the highest position, giving100=4.

## Line-by-line reasoning

- `public static int solve(int left,int right) {` — Restrict the range to nonnegative signed-int values.
- `if(left<0||left>right) throw new IllegalArgumentException("invalid range");` — Ordered nonnegative bounds define the inclusive interval.
- `int shifts=0;` — Count low bits known to vary somewhere across the interval.
- `while(left!=right) { left>>>=1; right>>>=1; shifts++; }` — Remove differing suffix bits until both endpoints share one prefix.
- `return left<<shifts;` — Every removed bit contributes zero to the full-range AND.

## Complexity and tradeoffs

O(31) time and O(1) space.

## Cases to practise

- `solve(5,7)` → `4`: A range with a shared high prefix.
- `solve(0,Integer.MAX_VALUE)` → `0`: Including zero clears all bits.
- `solve(9,9)` → `9`: A singleton range preserves its value.
