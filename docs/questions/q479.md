# Q479 — Recover two distinct unpaired values with XOR partitioning

**Topic:** Bit partitions · **Level:** Medium

## Problem and accepted inputs

Exactly two distinct int values occur once; every other value occurs twice. Return the two singletons in ascending numeric order.

## Example

```java
solve(new int[]{1,2,1,3,2,5})
```

Expected Java value: `new int[]{3,5}`.

Expected printed output (verified):

```text
[3, 5]
```

## How, why, and where to use it

XORing everything gives a XOR b, whose set bit marks a position where the singletons differ. Partition all values by that bit: paired values stay together and cancel, while the singletons land in opposite groups. Useful for recovering two odd-parity records under strict assumptions.

## Worked trace

For[1,2,1,3,2,5], combined XOR is3 XOR5=6. Its lowest set bit separates3 and5.

- `public static int[] solve(int[] a) {` — First identify a bit that distinguishes the two promised singleton values.
- `int combined=0; for(int value:a) combined^=value;` — Paired values disappear, leaving the XOR of the singletons.
- `if(combined==0) throw new IllegalArgumentException("two distinct singles required");` — Distinct singleton bit patterns must differ somewhere.
- `int distinguishing=combined&-combined,first=0,second=0;` — Isolate the lowest set bit, including the sign bit if necessary.
- `for(int value:a) { if((value&distinguishing)==0) first^=value; else second^=value; }` — Equal pairs share a partition and cancel within it.
- `return first<second?new int[]{first,second}:new int[]{second,first};` — Define deterministic ascending output order.

## Complexity and tradeoffs

O(n) time and O(1) working space plus a two-element result.
