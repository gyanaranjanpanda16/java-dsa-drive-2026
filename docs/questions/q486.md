# Q486 — Generate every prime up to a limit

**Topic:** Sieve of Eratosthenes · **Level:** Easy

## Problem and accepted inputs

Return primes in[2,limit] for0<=limit<=10000000.

## Example

```java
solve(10)
```

Expected Java value: `List.of(2,3,5,7)`.

Expected printed output (verified):

```text
[2, 3, 5, 7]
```

## How, why, and where to use it

Every composite has a prime factor at most its square root. Mark multiples of each still-unmarked p beginning at p² because smaller multiples already have a smaller prime factor. This efficiently preprocesses many primality answers in a bounded universe.

## Worked trace

For limit10, mark4,6,8,10 from2 and9 from3; unmarked2,3,5,7 are prime.

## Line-by-line reasoning

- `public static List<Integer> solve(int limit) {` — Generate a bounded batch rather than test each candidate independently.
- `if(limit<0||limit>10000000) throw new IllegalArgumentException("limit outside supported range");` — Prevent invalid or unintended huge arrays.
- `boolean[] composite=new boolean[limit+1];` — False initially means no prime factor has yet disproved primality.
- `for(int p=2;p<=limit/p;p++) if(!composite[p]) {` — Only primes up to the square root need to mark multiples.
- `for(int multiple=p*p;multiple<=limit;multiple+=p) composite[multiple]=true;` — Smaller multiples were already handled by earlier factors.
- `List<Integer> primes=new ArrayList<>(); for(int value=2;value<=limit;value++) if(!composite[value]) primes.add(value);` — Exclude0 and1 explicitly.
- `return primes;` — Increasing traversal yields sorted prime values.

## Complexity and tradeoffs

O(limit log log(limit+2)) time and O(limit) storage plus output.

- `solve(10)` → `List.of(2,3,5,7)`: A range containing primes and composites.
- `solve(1)` → `List.of()`: No primes below2.
- `solve(2)` → `List.of(2)`: The first prime is included.
