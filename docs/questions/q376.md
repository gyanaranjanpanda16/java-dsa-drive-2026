# Q376 — Flatten nested integer lists in order

**Topic:** Recursive decomposition · **Level:** Easy

## Problem and accepted inputs

Accept a finite, acyclic List whose elements are Integer or further Lists of the same form. Return all integers in left-to-right depth-first order. Empty nested lists contribute nothing; other element types and null elements are rejected. Nesting must fit the Java call stack.

## Example

```java
solve(List.of(1,List.of(2,List.of(),List.of(3)),4))
```

Expected Java value: `List.of(1,2,3,4)`.

Expected printed output (verified):

```text
[1, 2, 3, 4]
```

## How, why, and where to use it

A fixed number of nested loops only handles a fixed depth. Recursion handles the same contract at every depth: flatten a child list completely before visiting its next sibling. The output accumulated so far is always the flattened prefix already visited. This is the core traversal idea behind nested configuration values and document trees; cycles would require a separate visited-object policy.

## Worked trace

For [1,[2,[],[3]],4], append1, then enter the second element. Append2, skip the empty list, enter [3] and append3. Returning twice resumes the outer list, which appends4. The result is [1,2,3,4]; returning from recursion preserves where each parent traversal paused.

## Line-by-line reasoning

- `public static List<Integer> solve(List<?> nested) {` — Wildcards allow lists nested to different depths.
- `List<Integer> output=new ArrayList<>();` — One accumulator avoids repeatedly copying child results.
- `flatten(nested,output);` — Visit the whole outer list in encounter order.
- `return output;` — The caller receives a new flat list.
- `private static void flatten(List<?> nested,List<Integer> output) {` — Each call handles one list completely.
- `for(Object value:nested) {` — Preserve the source order among siblings.
- `if(value instanceof Integer number) output.add(number);` — Integers are leaves and contribute one output value.
- `else if(value instanceof List<?> child) flatten(child,output);` — Lists contribute their recursively flattened contents.
- `else throw new IllegalArgumentException("only integers and lists allowed");` — Do not silently drop unsupported values.

## Complexity and tradeoffs

O(N) time for N visited elements, O(D) call-stack space for depth D, plus O(K) output for K integers.

## Cases to practise

- `solve(List.of(1,List.of(2,List.of(),List.of(3)),4))` → `List.of(1,2,3,4)`: Multiple depths and an empty nested list.
- `solve(List.of())` → `List.of()`: Empty outer list.
- `solve(List.of(List.of(-1),List.of(-1)))` → `List.of(-1,-1)`: Keep repeated values and signs.
