# Q300 — Find k pairs with the smallest sums

**Topic:** Heap frontier · **Level:** Medium

## Question and contract

Find k pairs with the smallest sums. Implement the operation exposed by `String solve(int[] a,int[] b,int k)`. Both arrays nondecreasing; pairs refer to distinct index combinations; k>=0.

## Runnable example

```java
solve(new int[]{1,7},new int[]{2,4},3)
```

Expected output:

```text
[[1, 2], [1, 4], [7, 2]]
```

## How and why the answer works

For each fixed index in a, adding sorted b produces a sorted row of sums. A heap merges these rows exactly as it merges sorted feeds, avoiding materializing every pair.

## Walkthrough

For lists [1,7] and [2,4], candidate pair sums are 3,5,9,11. The first three pairs are(1,2),(1,4),(7,2). After emitting one pair from a row, advance only that row's second-list index. This merges sorted pair-sum rows without materializing the full Cartesian product.

## Complexity and tradeoffs

O(n log(n+1)+min(k,nm) log(n+1)) time; O(n) heap plus output. This cost describes the supplied representation and stated input contract. A more general version may need extra validation or a different representation; do not silently extend the assumptions.

- `if(k<0) throw new IllegalArgumentException("negative count");` — Zero pairs is a valid request.
- `PriorityQueue<int[]> heap=new PriorityQueue<>((x,y)->{` — Compare pair cursors by exact long sums.
- `int order=Long.compare((long)a[x[0]]+b[x[1]],(long)a[y[0]]+b[y[1]]);` — Widen before addition to avoid int overflow.
- `if(order!=0) return order;` — Smaller sums must be output first.
- `if(b.length>0) for(int i=0;i<a.length;i++) heap.offer(new int[]{i,0});` — Each fixed-a row is a sorted sequence of pair sums.
- `List<String> result=new ArrayList<>();` — Preserve repeated index pairs even when values coincide.
- `if(++cursor[1]<b.length) heap.offer(cursor);` — Advance only the row just consumed.
- `return result.toString();` — Output ordering follows sum, then original indices.
