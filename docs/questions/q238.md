# Q238 — Find the first sorted value strictly greater than a target

**Topic:** Binary-search boundaries · **Level:** Easy

## Problem and accepted inputs

Return the first index with a[index]>target in a nondecreasing array, or length if none.

## Example

```java
solve(new int[]{1,2,2,4},2)
```

Expected Java value: `3`.

Expected printed output (verified):

```text
3
```

## How, why, and where to use it

The boundary separates values at most target from strictly larger values. Unlike lower bound, equality belongs to the discarded left side. Combining both boundaries counts duplicates or selects inclusive value ranges.

## Worked trace

For[1,2,2,4], upperBound(2)=3, after both equal entries.

## Line-by-line reasoning

- `public static int solve(int[] a,int target) {` — Locate the exclusive end of target's equal-value range.
- `int low=0,high=a.length;` — Include the end position as a valid boundary answer.
- `while(low<high) {` — Each comparison strictly shrinks the candidate boundary interval.
- `int middle=low+(high-low)/2;` — Avoid overflowing the midpoint calculation.
- `if(a[middle]<=target) low=middle+1; else high=middle;` — Equal entries must precede the first strictly greater value.
- `return low;` — This boundary can be subtracted from a lower bound to count equal entries.

## Complexity and tradeoffs

O(log(n+1)) time and O(1) space.

## Cases to practise

- `solve(new int[]{1,2,2,4},2)` → `3`: Skip the entire equal run.
- `solve(new int[]{1,2},0)` → `0`: All values are greater.
- `solve(new int[]{},0)` → `0`: Empty array boundary.
