# Q250 — Sort signed ints using four stable byte passes

**Topic:** Radix sorting · **Level:** Medium

## Problem and accepted inputs

Return an ascending copy of arbitrary signed32-bit integers using least-significant-byte radix sort.

## Example

```java
solve(new int[]{3,-1,Integer.MIN_VALUE,0,Integer.MAX_VALUE})
```

Expected Java value: `new int[]{Integer.MIN_VALUE,-1,0,3,Integer.MAX_VALUE}`.

Expected printed output (verified):

```text
[-2147483648, -1, 0, 3, 2147483647]
```

## How, why, and where to use it

Stable passes preserve previously ordered lower bytes. Flipping the sign bit transforms signed numeric order into unsigned bit-pattern order; sorting all four transformed bytes therefore gives signed order without comparisons. Useful for large fixed-width numeric batches.

## Worked trace

Integer.MIN_VALUE transforms to unsigned0, while Integer.MAX_VALUE transforms to unsigned4294967295; their final order is correct.

## Line-by-line reasoning

- `public static int[] solve(int[] input) {` — Treat signed values through an order-preserving bit transformation.
- `int[] a=input.clone(),buffer=new int[a.length];` — Alternate source and destination buffers on each pass.
- `for(int shift=0;shift<32;shift+=8) {` — Process bytes from least significant to most significant.
- `int[] next=new int[256];` — One counter per possible byte value.
- `for(int value:a) next[((value^Integer.MIN_VALUE)>>>shift)&255]++;` — Count transformed byte frequencies using unsigned shift.
- `int total=0;` — Convert frequencies into the starting offset of each byte bucket.
- `for(int key=0;key<256;key++) { int count=next[key]; next[key]=total; total+=count; }` — Prefix totals reserve consecutive bucket ranges.
- `for(int value:a) buffer[next[((value^Integer.MIN_VALUE)>>>shift)&255]++]=value;` — Forward traversal preserves stability inside each bucket.
- `int[] saved=a; a=buffer; buffer=saved;` — The completed pass becomes the next pass's input without copying.
- `return a;` — All32 transformed bits are now ordered from most to least significant.

## Complexity and tradeoffs

O(4*(n+256)) time and O(n+256) auxiliary space.

- `solve(new int[]{3,-1,Integer.MIN_VALUE,0,Integer.MAX_VALUE})` → `new int[]{Integer.MIN_VALUE,-1,0,3,Integer.MAX_VALUE}`: Both signed extremes and zero.
- `solve(new int[]{})` → `new int[]{}`: Empty buffers remain empty.
- `solve(new int[]{-2,-2,-3})` → `new int[]{-3,-2,-2}`: Negative duplicates retain their multiplicity.
