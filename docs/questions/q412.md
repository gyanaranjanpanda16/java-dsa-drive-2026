# Q412 — Coin Combination Count

**Topic:** Dynamic programming · **Difficulty:** Medium

## Question and contract

Implement `Coin Combination Count` using the operation demonstrated below. Distinct positive denominations; unlimited supply; count unordered combinations for a nonnegative feasible table size.

## Demonstration

```java
count(new int[]{1,2,5},5)
```

Expected output:

```text
4
```

## How and why

Processing coin types outside the amount loop gives each multiset a canonical type order. The recurrence adds combinations containing another copy of the current coin without creating different orderings of identical choices.

## Complexity and tradeoffs

O(amount*coinCount) time and O(amount+coinCount) space; overflow is reported.

Use the input domain above when judging whether the state space fits memory and whether arithmetic fits the chosen numeric type. Recursive output-generation problems have an unavoidable cost proportional to their output; avoid using them on unrestricted large inputs.

- `if(amount<0) throw new IllegalArgumentException("Nonnegative amount required");` — A negative target is outside the counting domain.
- `Set<Integer> unique=new HashSet<>();` — Duplicate denominations would otherwise count the same combination repeatedly.
- `long[] dp=new long[amount+1]; dp[0]=1;` — One empty multiset makes amount zero.
- `for(int coin:coins) {` — Finish one denomination before introducing the next to avoid counting permutations.
- `for(int sum=coin;sum<=amount;sum++) dp[sum]=Math.addExact(dp[sum],dp[sum-coin]);` — Increasing totals permit unlimited copies of the current coin.
