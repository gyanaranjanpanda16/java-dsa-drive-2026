# Q239 — Search a rotated sorted array with distinct values

**Topic:** Modified binary search · **Level:** Medium

## Problem and accepted inputs

Return target index or-1 in a rotation of a strictly increasing int array.

## Example

```java
solve(new int[]{4,5,6,7,0,1,2},0)
```

Expected Java value: `4`.

Expected printed output (verified):

```text
4
```

## How, why, and where to use it

At least one half around the midpoint is sorted. Test whether target lies within that half before eliminating it or choosing it. This preserves logarithmic search after a cyclic shift of an ordered sequence.

## Worked trace

For[4,5,6,7,0,1,2], target0 is outside the sorted left half and is found in the right half.

## Line-by-line reasoning

- `public static int solve(int[] a,int target) {` — Exploit one sorted half even though the full array wraps once.
- `int low=0,high=a.length-1;` — Begin with every position still possible.
- `while(low<=high) {` — Continue while at least one candidate remains.
- `int middle=low+(high-low)/2; if(a[middle]==target) return middle;` — A direct match ends the search.
- `if(a[low]<=a[middle]) {` — With distinct keys, the left half is monotonically ordered.
- `if(a[low]<=target && target<a[middle]) high=middle-1; else low=middle+1;` — Keep that half only when its value bounds include target.
- `} else {` — The rotation break is on the left, so the right half is sorted.
- `if(a[middle]<target && target<=a[high]) low=middle+1; else high=middle-1;` — Use the right half's value bounds symmetrically.
- `return -1;` — Target lies in neither surviving range.

## Complexity and tradeoffs

O(log(n+1)) time and O(1) space; distinctness is required for this elimination rule.

## Cases to practise

- `solve(new int[]{4,5,6,7,0,1,2},0)` → `4`: Target lies after the rotation break.
- `solve(new int[]{1,2,3},2)` → `1`: Unrotated input still works.
- `solve(new int[]{},4)` → `-1`: Empty input has no target.
