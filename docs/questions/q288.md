# Q288 — Return the k largest values in descending order

**Topic:** Heaps · **Level:** Medium

## Question and contract

Return the k largest values in descending order. Implement the operation exposed by `String solve(int[] a,int k)`. 0<=k<=length; input is not modified.

## Runnable example

```java
solve(new int[]{4,1,9,3,9},3)
```

Expected output:

```text
[9, 9, 4]
```

## How and why the answer works

A bounded min-heap retains the k largest occurrences. Repeated polling sorts those candidates ascending; reversing only the k outputs avoids sorting the entire input.

## Walkthrough

Among [4,1,9,3,9], a size-three min heap ultimately retains 4,9,9. Sorting those retained values descending produces [9,9,4]. Both occurrences of 9 count: this asks for top elements with multiplicity, not top distinct values. The heap bounds retained storage by k rather than n.

## Complexity and tradeoffs

O(n log(k+1)+k log(k+1)) time; O(k) auxiliary/output space. This cost describes the supplied representation and stated input contract. A more general version may need extra validation or a different representation; do not silently extend the assumptions.

## Read the important code decisions

These statements connect the algorithm to Java. Follow how each one changes the state used by the next statement; the linked answer contains the complete method.

- `PriorityQueue<Integer> heap=new PriorityQueue<>();` — Keep the current top-k boundary at the root.
- `for(int value:a) {` — Every input occurrence remains eligible independently.
- `heap.offer(value);` — Add the next candidate before trimming excess capacity.
- `if(heap.size()>k) heap.poll();` — Remove the least useful retained occurrence.
- `List<Integer> result=new ArrayList<>();` — Collect heap removals in a predictable order.
- `while(!heap.isEmpty()) result.add(heap.poll());` — Polling emits ascending order, unlike heap iteration.
- `Collections.reverse(result);` — Reverse once to satisfy descending presentation.
