# Q398 — Recursive Digit Decodings

**Topic:** Recursion and backtracking · **Difficulty:** Medium

## Question and contract

Implement `Recursive Digit Decodings` using the operation demonstrated below. ASCII digits, short strings, count fits long; empty text has one empty decoding.

## Demonstration

```java
count("226")
```

Expected printed output (verified):

```text
3
```

## How and why

A decoding begins with one digit or a valid pair. These disjoint choices lead to smaller suffixes; a leading zero invalidates that suffix immediately.

The source includes comments at each meaningful line. Start by naming the state, identify the stopping or initialization case, and then follow how a smaller solved state or an accepted choice contributes to the answer. Do not memorize the loop order without the state definition.

## Walkthrough

226 decodes as 2|2|6, 22|6, and 2|26.

## Complexity and tradeoffs

Exponential time without memoization, O(n) stack; later DP removes repeated suffix work.

Use the input domain above when judging whether the state space fits memory and whether arithmetic fits the chosen numeric type. Recursive output-generation problems have an unavoidable cost proportional to their output; avoid using them on unrestricted large inputs.

## Checks and practice

`selfTest()` checks 4 independently expected cases, including small or boundary inputs. Before opening the solution, predict the sample and derive a simpler baseline. After solving, change one input condition and explain which part of the proof would need to change.
