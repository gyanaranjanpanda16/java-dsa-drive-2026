# Q121 — Contrast a read-only live view with a detached snapshot

**Topic:** Java Collections: unmodifiableList · **Level:** Beginner

## Question and contract

Return [unmodifiable live view, detached immutable snapshot] after appending to their original source. Unmodifiable describes what a reference allows, not whether the underlying data can ever change. This distinction matters when exposing internal state through public APIs. Require non-null elements.

Implement `List<List<String>> solve(List<String> input, String appended)`. The examples below define concrete accepted inputs and expected answers. Unless stated otherwise, reference inputs must be non-null; unsupported input violates the method's contract. Read the validation and comments in the source for additional restrictions.

## Example and answer

Input arguments: `List.of("a"),"b"`

Expected Java value: `List.of(List.of("a","b"),List.of("a"))`

Expected printed output (verified):

```text
[[a, b], [a]]
```

## How and why the answer works

Return [unmodifiable live view, detached immutable snapshot] after appending to their original source. Unmodifiable describes what a reference allows, not whether the underlying data can ever change. This distinction matters when exposing internal state through public APIs. Require non-null elements.

Follow the state in this order for the sample input; each explanation corresponds to a line in the solution:

- `List<String> source = new ArrayList<>(input);` — Keep a mutable backing list owned by this example.
- `List<String> view = Collections.unmodifiableList(source);` — Block mutations through this reference while retaining the backing list relationship.
- `List<String> snapshot = List.copyOf(source);` — Capture current non-null membership independently of future structural changes.
- `source.add(appended);` — Mutation through the original mutable reference is still permitted.
- `return List.of(view,snapshot);` — The view sees the appended value; the snapshot retains its earlier membership.

## Cost and alternatives

O(n) time and O(n) space for copies; wrapping an unmodifiable view alone is O(1). Choose this approach when the stated operations and input constraints match the problem. Before reading the code, write a small manual example and identify the work that would otherwise be repeated.
