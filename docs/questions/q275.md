# Q275 — Find the greatest BST key not exceeding a target

**Topic:** Trees and BST · **Level:** Intermediate

## Question and contract

Find the greatest BST key not exceeding a target. Implement the operation exposed by `Integer solve(Node root,int key)`. Input is a valid BST; null means no floor exists.

## Runnable example

```java
solve(sample(),5)
```

Expected output:

```text
5
```

## How and why the answer works

When a node is at most the target, it becomes a candidate and only its right subtree can improve it. Otherwise only the left subtree can contain a valid answer.

## Walkthrough

The sample tree has root `4`, children `2` and `6`, and leaf pairs `1,3` below `2` and `5,7` below `6`.

For target 5, root 4 is a legal floor candidate because 4<=5, but the right subtree may improve it. At 6 move left because 6 is too large. Node 5 equals the target, giving the best possible floor 5. A missing exact match would leave the greatest remembered value below the target.

## Read the important code decisions

These statements connect the algorithm to Java. Follow how each one changes the state used by the next statement; the linked answer contains the complete method.

- `int value; Node left, right;` — Child references encode hierarchy; null means no child.
- `Node(int value) { this.value = value; }` — A fresh node starts as a leaf.
- `Integer answer=null;` — Null distinguishes no floor from any actual integer key.
- `if(root.value<=key) { answer=root.value; root=root.right; }` — A valid floor may be improved only by a larger key.
- `else root=root.left;` — An oversized key and its right subtree cannot be a floor.
- `return answer;` — The last admissible candidate is the greatest one.
