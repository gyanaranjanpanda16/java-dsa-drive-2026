# Q244 — Sort with adjacent exchanges and an early-stop check

**Topic:** Elementary sorting · **Level:** Easy

## Problem and accepted inputs

Return a sorted copy of an int array using bubble sort; leave the input unchanged.

## Example

```java
solve(new int[]{3,1,2})
```

Expected Java value: `new int[]{1,2,3}`.

Expected printed output (verified):

```text
[1, 2, 3]
```

## How, why, and where to use it

An adjacent inverted pair can be swapped without disturbing any other pair order. Each pass moves the largest unresolved value to the right; positions after the final swap are already settled. This teaches local inversion repair and adaptive early stopping.

## Worked trace

[3,1,2] becomes[1,3,2] then[1,2,3] in the first pass; the next pass finds no swap.

## Line-by-line reasoning

- `public static int[] solve(int[] input) {` — Preserve caller-owned data by sorting a copy.
- `int[] a=input.clone(); int end=a.length-1;` — The suffix beyond end is already in final order.
- `while(end>0) {` — At least two unresolved positions are required for a comparison.
- `int last=0;` — Zero records that no out-of-order pair has been found yet.
- `for(int i=0;i<end;i++) if(a[i]>a[i+1]) {` — Swap only strict inversions, retaining stability for equal values.
- `int saved=a[i]; a[i]=a[i+1]; a[i+1]=saved; last=i;` — Move the larger value right and remember the final changed boundary.
- `end=last;` — The remaining suffix had no later inversions and needs no further work.
- `return a;` — Every adjacent pair is now ordered.

## Complexity and tradeoffs

O(n²) worst-case and O(n) best-case time; O(n) returned copy and O(1) extra sorting state.

## Cases to practise

- `solve(new int[]{3,1,2})` → `new int[]{1,2,3}`: Several adjacent exchanges.
- `solve(new int[]{})` → `new int[]{}`: Empty input.
- `solve(new int[]{2,2,-1})` → `new int[]{-1,2,2}`: Duplicates and a negative value.
