# Q345 — Count directed source-to-target paths in a DAG

**Topic:** Graphs · **Level:** Medium

## Question and contract

Count directed source-to-target paths in a DAG. Implement the operation exposed by `String solve(int n,int[][] edges,int source,int target)`. Directed simple graph; n>=1; valid source and target; no parallel edges. Returns CYCLE for any cycle; counts must fit signed long or ArithmeticException is raised. The empty source-to-itself path counts once.

## Runnable example

```java
solve(4,new int[][]{{0,1},{0,2},{1,3},{2,3},{0,3}},0,3)
```

Expected output:

```text
3
```

## How and why the answer works

Each source-to-v path has a unique last incoming edge, so summing predecessor counts neither omits nor double-counts paths in a DAG. A topological sweep makes these sums final in dependency order. This counts alternatives through workflows or acyclic routing systems; Java long stores exact bounded counts and Math.addExact rejects overflow.

## Walkthrough

The diamond contributes 0→1→3 and 0→2→3, and the direct edge 0→3 contributes a third path. Accumulate predecessor path counts in topological order so paths to each node are counted before being forwarded. The result is 3; ordinary reachability would only say the destination is reachable.

## Complexity and tradeoffs

O(V+E) time and space. This cost describes the supplied representation and stated input contract. A more general version may need extra validation or a different representation; do not silently extend the assumptions.

## Checks and edge cases

- Two indirect paths and one direct path.
- Unreachable target.
- The empty path counts when source equals target.
