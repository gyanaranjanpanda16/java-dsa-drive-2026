# Q236 — Search a sorted array by halving the candidate interval

**Topic:** Binary search · **Level:** Easy

## Problem and accepted inputs

Return an index containing target in a nondecreasing int array, or-1 when absent. Any matching index is acceptable for duplicates.

## Example

```java
solve(new int[]{1,3,5,7,9},7)
```

Expected Java value: `3`.

Expected printed output (verified):

```text
3
```

## How, why, and where to use it

Maintain that any still-possible match lies between low and high inclusive. Comparing the middle value eliminates the half that ordering proves cannot contain the target. This is the core search operation on sorted indexes.

## Worked trace

Searching7 in[1,3,5,7,9] first compares5, then7 and returns index3.

## Line-by-line reasoning

- `public static int solve(int[] a,int target) {` — Assume ordering has already been established by the caller.
- `int low=0,high=a.length-1;` — The full array initially contains all candidate positions.
- `while(low<=high) {` — An empty candidate interval proves absence.
- `int middle=low+(high-low)/2;` — Avoid overflow from adding two large indices.
- `if(a[middle]==target) return middle;` — Equality identifies a valid answer immediately.
- `if(a[middle]<target) low=middle+1; else high=middle-1;` — Exclude the tested midpoint and the impossible sorted half.
- `return -1;` — No candidate survived the comparisons.

## Complexity and tradeoffs

O(log(n+1)) time and O(1) space.

## Cases to practise

- `solve(new int[]{1,3,5,7,9},7)` → `3`: A target in the upper half.
- `solve(new int[]{},1)` → `-1`: Empty candidate interval.
- `solve(new int[]{2,4},3)` → `-1`: An absent value between entries.
