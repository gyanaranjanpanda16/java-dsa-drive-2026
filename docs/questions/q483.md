# Q483 — Generate a sequence whose adjacent bitmasks differ by one bit

**Topic:** Gray-code construction · **Level:** Medium

## Problem and accepted inputs

For0<=bits<=16, return all2^bits reflected Gray codes starting at zero. Adjacent codes, including last-to-first for positive bits, differ in exactly one bit.

## Example

```java
solve(2)
```

Expected Java value: `new int[]{0,1,3,2}`.

Expected printed output (verified):

```text
[0, 1, 3, 2]
```

## How, why, and where to use it

The formula i XOR(i shifted right) converts binary carry changes into a single Gray-bit change. This creates a complete fixed-width traversal with minimal adjacent changes, useful in state encoding and subset-order exercises.

## Worked trace

For2 bits, binary0,1,2,3 maps to Gray0,1,3,2.

## Line-by-line reasoning

- `public static int[] solve(int bits) {` — Keep the exponential output explicitly bounded for this demonstration.
- `if(bits<0||bits>16) throw new IllegalArgumentException("require zero to sixteen bits");` — Reject impractical or invalid output sizes.
- `int[] codes=new int[1<<bits];` — Every possible bit pattern appears exactly once.
- `for(int i=0;i<codes.length;i++) codes[i]=i^(i>>>1);` — Adjacent binary carry patterns cancel down to one changed Gray bit.
- `return codes;` — Zero bits yields the one empty-pattern value zero.

## Complexity and tradeoffs

O(2^bits) time and output space; the bound prevents accidental exponential allocation.
