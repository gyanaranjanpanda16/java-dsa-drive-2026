# Q397 — Restore IPv4 Addresses

**Topic:** Recursion and backtracking · **Difficulty:** Medium

## Question and contract

Implement `Restore IPv4 Addresses` using the operation demonstrated below. ASCII decimal digits only; four pieces in 0..255 with no multi-digit leading zeros.

## Demonstration

```java
restore("25525511135")
```

Expected printed output (verified):

```text
[255.255.11.135, 255.255.111.35]
```

## How and why

Each valid address corresponds to one choice of four octet lengths. Length pruning and octet validation reject exactly the invalid branches.

## Complexity and tradeoffs

At most 3^4 length choices; O(n) digit validation plus constant bounded search, O(1) depth excluding output.

Use the input domain above when judging whether the state space fits memory and whether arithmetic fits the chosen numeric type. Recursive output-generation problems have an unavoidable cost proportional to their output; avoid using them on unrestricted large inputs.

## Read the important code decisions

These statements connect the algorithm to Java. Follow how each one changes the state used by the next statement; the linked answer contains the complete method.

- `List<String> out=new ArrayList<>();` — Collect addresses with exactly four valid pieces.
- `return out;` — Impossible input lengths naturally produce no result.
- `int left=4-parts.size();` — Count how many address pieces still need values.
- `if(s.length()-i<left || s.length()-i>3*left) return;` — Each remaining piece uses between one and three digits.
- `if(left==0) { out.add(String.join(".",parts)); return; }` — The length check ensures all digits have been consumed.
- `String p=s.substring(i,i+len);` — A candidate preserves the original digit order.
- `if((len>1&&p.charAt(0)=='0')||Integer.parseInt(p)>255) continue;` — Reject leading zeros and out-of-range octets.
- `parts.add(p); split(s,i+len,parts,out); parts.remove(parts.size()-1);` — Explore this octet, then release it.
