# Q377 — Generate subsets without duplicate combinations

**Topic:** Backtracking with duplicate skipping · **Level:** Medium

## Problem and accepted inputs

Given int values, return all distinct subsets, including the empty subset. Sort each subset ascending and emit subsets in depth-first order. Equal input values are separate available copies, but equal output combinations appear only once. Input is not mutated; output grows exponentially.

## Example

```java
solve(new int[]{1,2,2})
```

Expected Java value: `List.of(List.of(),List.of(1),List.of(1,2),List.of(1,2,2),List.of(2),List.of(2,2))`.

Expected printed output (verified):

```text
[[], [1], [1, 2], [1, 2, 2], [2], [2, 2]]
```

## How, why, and where to use it

Generating every position subset and deduplicating later wastes memory. Sort a copy first, then skip equal choices at the same recursion depth. Equal values are still allowed at deeper levels, so [2,2] is retained when two copies exist. Each recursion state is one already valid subset; extending only with later positions prevents permutations of the same choice. This models selecting distinct inventory combinations when items have repeated values.

## Worked trace

For [1,2,2], emit [] at the root. Choose1 and emit [1]; then choose2 and emit [1,2], then the next2 gives [1,2,2]. Back at the level after1, skip the second2 because that branch would repeat [1,2]. Starting with2 gives [2] and [2,2].

## Line-by-line reasoning

- `public static List<List<Integer>> solve(int[] values) {` — Return combinations rather than subsets of position identifiers.
- `int[] sorted=values.clone(); Arrays.sort(sorted);` — Adjacent equal values make duplicate choices detectable.
- `List<List<Integer>> output=new ArrayList<>();` — Each stored subset must be an independent snapshot.
- `subsets(sorted,0,new ArrayList<>(),output);` — Initially no position has been chosen.
- `return output;` — Even empty input has the empty subset.
- `private static void subsets(int[] values,int start,List<Integer> path,List<List<Integer>> output) {` — Only positions at or after start remain available.
- `output.add(new ArrayList<>(path));` — Copy before later backtracking changes the path.
- `for(int i=start;i<values.length;i++) {` — Try each possible next value.
- `if(i>start&&values[i]==values[i-1]) continue;` — Skip equivalent sibling branches, not repeated values at deeper levels.
- `path.add(values[i]);` — Choose one available occurrence.
- `subsets(values,i+1,path,output);` — This occurrence cannot be selected again.
- `path.remove(path.size()-1);` — Restore the parent's subset for the next choice.

## Complexity and tradeoffs

O(n log n + n*2^n) worst-case time, O(n) working space plus O(n*2^n) output. Duplicate skipping can reduce the actual output greatly.

## Cases to practise

- `solve(new int[]{1,2,2})` → `List.of(List.of(),List.of(1),List.of(1,2),List.of(1,2,2),List.of(2),List.of(2,2))`: Duplicate input does not duplicate output.
- `solve(new int[]{})` → `List.of(List.of())`: The empty subset is still present.
- `solve(new int[]{2,2})` → `List.of(List.of(),List.of(2),List.of(2,2))`: Both copies may be selected.
