# Q383 — Match a pattern to distinct variable-length substrings

**Topic:** Backtracking and bijections · **Level:** Hard

## Problem and accepted inputs

For a pattern of at most10 UTF-16 chars and text of at most20 UTF-16 chars, decide whether each distinct pattern char can map to a distinct nonempty substring so their concatenation equals the whole text. Repeated pattern chars must reuse the same substring. Both empty inputs match; only one empty input does not.

## Example

```java
solve("abab","redblueredblue")
```

Expected Java value: `true`.

Expected printed output (verified):

```text
true
```

## How, why, and where to use it

Unlike mapping words separated by spaces, substring boundaries are unknown. Backtracking tries every nonempty candidate for a new pattern symbol. A map enforces consistent reuse and a set enforces injectivity: two symbols cannot share one substring. Existing assignments consume fixed prefixes, which prunes most branches. This models matching a small symbolic template against an unsegmented message.

## Worked trace

For pattern abab and text redblueredblue, one branch assigns a=red,b=blue. Reusing a consumes the next red and reusing b consumes the last blue, exhausting both inputs together. For ab and xx, assigning both symbols x is forbidden, and any longer first assignment leaves no nonempty second substring.

## Line-by-line reasoning

- `public static boolean solve(String pattern,String text) {` — Bound the intentionally exponential search.
- `if(pattern.length()>10||text.length()>20) throw new IllegalArgumentException("pattern<=10 and text<=20 required");` — Large inputs need a separate performance policy.
- `return match(pattern,text,0,0,new HashMap<>(),new HashSet<>());` — Start with no symbol assignments.
- `private static boolean match(String pattern,String text,int p,int t,Map<Character,String> mapping,Set<String> used) {` — Indices mark the unmatched suffixes.
- `if(p==pattern.length()) return t==text.length();` — Matching a prefix alone is insufficient.
- `char symbol=pattern.charAt(p); String assigned=mapping.get(symbol);` — Repeated symbols must reuse their earlier spelling.
- `if(assigned!=null) return text.startsWith(assigned,t)&&match(pattern,text,p+1,t+assigned.length(),mapping,used);` — Consume exactly the fixed assignment if it matches.
- `for(int end=t+1;end<=text.length();end++) {` — A new symbol may consume any nonempty prefix.
- `String candidate=text.substring(t,end); if(!used.add(candidate)) continue;` — Distinct symbols must map to distinct strings.
- `mapping.put(symbol,candidate);` — Tentatively bind this previously unassigned symbol.
- `if(match(pattern,text,p+1,end,mapping,used)) return true;` — A complete matching assignment proves existence.
- `mapping.remove(symbol); used.remove(candidate);` — Undo both halves of the bijection before another candidate.
- `return false;` — No legal nonempty candidate completed the match.

## Complexity and tradeoffs

O((m+1)^p * m) conservative exponential time for pattern length p and text length m. O(p*m) assignment storage plus recursion; small input bounds are intentional.

## Cases to practise

- `solve("abab","redblueredblue")` → `true`: Repeated symbols consume repeated substrings.
- `solve("ab","xx")` → `false`: Different symbols cannot both mean x.
- `solve("","")` → `true`: Both inputs exhausted immediately.
- `solve("aaaa","xyzxyzxyzxyz")` → `true`: One substring reused four times.
