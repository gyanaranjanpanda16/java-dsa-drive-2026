# Q227 — Count zero-sum tuples from four arrays

**Topic:** Pair-sum hashing · **Level:** Medium

## Problem and accepted inputs

Count index tuples taking one int from each of four arrays whose total is zero. Duplicate occurrences count separately; the answer must fit long.

## Example

```java
solve(new int[]{1,2},new int[]{-2,-1},new int[]{-1,2},new int[]{0,2})
```

Expected Java value: `2L`.

Expected printed output (verified):

```text
2
```

## How, why, and where to use it

Store frequencies of all sums from the first two arrays, then query the negation of each sum from the other two. Every tuple splits uniquely into one stored and one queried pair. This meet-in-the-middle technique replaces a four-way enumeration.

## Worked trace

For A=[1,2], B=[-2,-1], C=[-1,2], D=[0,2], two indexed tuples sum to zero.

## Line-by-line reasoning

- `public static long solve(int[] a,int[] b,int[] c,int[] d) {` — Preserve indexed multiplicity rather than deduplicating equal values.
- `Map<Long,Long> sums=new HashMap<>();` — Long keys avoid overflow when two ints are added.
- `for(int x:a) for(int y:b) sums.merge((long)x+y,1L,Long::sum);` — Count every first-half pair exactly once.
- `long total=0;` — Accumulate the number of compatible full tuples.
- `for(int x:c) for(int y:d) total+=sums.getOrDefault(-((long)x+y),0L);` — A complementary sum is necessary and sufficient for total zero.
- `return total;` — Each second-half pair contributes every matching first-half pair.

## Complexity and tradeoffs

Expected O(ab+cd) time and O(ab) space for the four array lengths.

## Cases to practise

- `solve(new int[]{1,2},new int[]{-2,-1},new int[]{-1,2},new int[]{0,2})` → `2L`: Multiple sum combinations.
- `solve(new int[]{0,0},new int[]{0},new int[]{0},new int[]{0})` → `2L`: Duplicate occurrences are distinct choices.
- `solve(new int[]{},new int[]{1},new int[]{2},new int[]{3})` → `0L`: An empty array prevents any tuple.
