# Q462 — Maximize capital with at most k affordable projects

**Topic:** Greedy selection with two orderings · **Level:** Hard

## Problem and accepted inputs

Given equally sized arrays of nonnegative int required capital and profits, choose at most k distinct projects. A project is affordable when current capital meets its requirement; its profit is added after completion and the requirement is not spent. Start with nonnegative long capital. Return maximum final capital; reject an overflowing long result.

## Example

```java
solve(new int[]{0,1,1},new int[]{1,2,3},2,0)
```

Expected Java value: `4L`.

Expected printed output (verified):

```text
4
```

## How, why, and where to use it

Trying every project order is exponential. Sort projects by requirement, then maintain a max heap of profits for all currently affordable, unchosen projects. Choosing the largest affordable nonnegative profit gives at least as much next-step capital as any alternative, so it cannot reduce future options. Repeat at most k times. This is a simplified project-unlocking model, not a realistic investment recommendation: costs, durations, and risks would change the model.

## Worked trace

For requirements [0,1,1], profits [1,2,3], k2, initial0, only project0 is affordable. Select it and capital becomes1. Both remaining projects now enter the heap; select profit3 to finish at4. Selecting profit2 instead would finish at3.

## Line-by-line reasoning

- `public static long solve(int[] required,int[] profits,int k,long capital) {` — Capital requirements unlock projects without being deducted.
- `if(required.length!=profits.length||k<0||capital<0) throw new IllegalArgumentException("invalid sizes or bounds");` — Keep parallel arrays aligned and budgets nonnegative.
- `int[][] projects=new int[required.length][2];` — Copy requirements and profits into sortable records.
- `for(int i=0;i<required.length;i++) { if(required[i]<0||profits[i]<0) throw new IllegalArgumentException("nonnegative projects required"); projects[i]=new int[]{required[i],profits[i]}; }` — Negative profits would invalidate the greedy premise.
- `Arrays.sort(projects,Comparator.comparingInt(project->project[0]));` — Reveal projects in increasing affordability order.
- `PriorityQueue<Integer> available=new PriorityQueue<>(Comparator.reverseOrder()); int next=0;` — Keep the most profitable affordable project at the head.
- `for(int chosen=0;chosen<k;chosen++) {` — At most k distinct projects may be completed.
- `while(next<projects.length&&projects[next][0]<=capital) available.add(projects[next++][1]);` — Newly affordable projects become candidates exactly once.
- `if(available.isEmpty()) break;` — No remaining project can increase capital or unlock another one.
- `capital=Math.addExact(capital,available.remove());` — Add profit with explicit overflow detection.
- `return capital;` — Stopping before k selections is permitted.

## Complexity and tradeoffs

O(n log n + min(k,n) log n) time and O(n) extra space. Each project enters the heap once and is selected at most once.

## Cases to practise

- `solve(new int[]{0,1,1},new int[]{1,2,3},2,0)` → `4L`: An initial project unlocks better choices.
- `solve(new int[]{2},new int[]{9},1,0)` → `0L`: No affordable project.
- `solve(new int[]{0},new int[]{5},0,7)` → `7L`: No selections allowed.
- `solve(new int[]{0},new int[]{5},3,0)` → `5L`: A project cannot be selected twice.
