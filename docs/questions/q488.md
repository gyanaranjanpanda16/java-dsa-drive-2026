# Q488 — Raise a value to a large power modulo m

**Topic:** Exponentiation by squaring · **Level:** Medium

## Problem and accepted inputs

Return base^exponent mod modulus for any long base, nonnegative long exponent, and positive int modulus.

## Example

```java
solve(2,10,1000)
```

Expected Java value: `24L`.

Expected printed output (verified):

```text
24
```

## How, why, and where to use it

Represent the exponent in binary. Maintain the product of selected powers while repeatedly squaring the current power; reduce modulo m after each multiplication. Residues below an int modulus have products that fit long. Useful for cyclic arithmetic and large-power calculations.

## Worked trace

2^10 mod1000=1024 mod1000=24; only the exponent bits8 and2 need multiplication into the result.

## Line-by-line reasoning

- `public static long solve(long base,long exponent,int modulus) {` — Bound the modulus so residue products fit signed long.
- `if(exponent<0||modulus<=0) throw new IllegalArgumentException("invalid exponent or modulus");` — Negative powers need inverses rather than this algorithm.
- `long power=Math.floorMod(base,(long)modulus),result=1L%modulus;` — Normalize negative bases and handle modulus1 correctly.
- `while(exponent>0) {` — Consume one binary exponent digit each iteration.
- `if((exponent&1)!=0) result=result*power%modulus;` — Include this power exactly when its exponent bit is set.
- `power=power*power%modulus; exponent>>>=1;` — Square for the next binary place and discard the processed bit.
- `return result;` — The invariant preserves the original modular power throughout the loop.

## Complexity and tradeoffs

O(log(exponent+1)) modular multiplications and O(1) space.

## Cases to practise

- `solve(2,10,1000)` → `24L`: A power requiring multiple binary places.
- `solve(-2,3,5)` → `2L`: Negative base normalizes to a nonnegative residue.
- `solve(7,0,1)` → `0L`: Even the multiplicative identity is zero modulo1.
